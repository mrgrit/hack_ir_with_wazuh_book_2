## 범위 점검

- 1권: Module 01 실습 01~30 및 62. 총 31개, 11장과 부록.
- 2권: **31~61 및 63, 총 32개**. 1권의 실습 62는 선행 내용으로만 참조한다.
- 645~726쪽의 장기 분석 자료는 같은 슬라이드의 후반부다. Module 02·03으로 바꾸어 부르지 않는다.
- Module 02·03의 수록 권과 분량은 별도로 결정한다. 이번 저장소에 해당 모듈의 실습을 섞지 않는다.
- 실습별 본문은 준비 → 입력 → 응답 → Wazuh 수집·검색 → 조사·대응 → 원상복구 순서로 구성한다. 방어 판단과 실패 시 점검 순서가 빠지지 않게 검토한다.

## 후속 집필 시 반드시 바로잡을 해석

1. 4740을 도메인 컨트롤러에만 생기는 이벤트로 한정하지 않는다. 로컬 계정과 도메인 계정을 구분한다.
2. NTLM 로그온 또는 유형 9만으로 Pass-the-Hash를 확정하지 않는다. 실제 해시 사용과 정상 자격증명으로 징후를 만드는 재현을 구분한다.
3. 로그 삭제 이벤트가 모든 장애·우회 상황에서 반드시 보존·수집된다고 쓰지 않는다.
4. Defender 차단이 로그 전체의 부재를 뜻한다고 쓰지 않는다. 차단 전 활동과 Defender 기록을 따로 확인한다.
5. Office 자식 프로세스, 서비스·작업 생성, 관리자 로그온을 곧바로 침해로 판정하지 않는다.
6. 취약점 검색 0건은 수집·검사·인덱스 조건을 확인한 뒤 해석한다. 미보유를 자동 확정하지 않는다.
7. 규칙 레벨·MITRE 태그는 조사 단서다. 공격 성공·공격자 귀속의 증명과 구분한다.
8. 최근 8시간 이내 로그인에 후속 이벤트를 붙이는 방법은 휴리스틱이다. 동시 접속·계정 공유·NAT로 인한 오귀속을 평가한다.
9. 합성 자료의 정답 라벨과 점수를 실제 운영 환경의 침해 사실로 일반화하지 않는다.

## 최초 초안 산출물 이력

- 1~9장 초안과 복사용 예제, 출처·검증 기록을 작성했다. 2장 39쪽, 3장 41쪽, 4장 36쪽, 5장 36쪽, 6장 38쪽, 7장 35쪽, 8장 34쪽, 9장 40쪽이다.
- 2장은 실습 31~34의 제한된 RDP 입력과 로그 대조, 3장은 실습 35~37·50의 정상 인증·비활성 계정·감사 정책 변경과 원상복구를 확인했다. 해시 추출·Pass-the-Hash·외부 호스트 이동은 수행하지 않았다.
- 4장은 서비스·작업·Run 등록과 osquery 상태를, 5장은 문구 출력·파일 변환·모의 부모 프로그램의 실행 기록을 확인했다. 실제 악성코드·Office 매크로·보호 기능 해제는 실행하지 않았다.
- 6장은 실습 43·47·48의 LSASS 접근·HTTP·DNS 분석이다. 새 자격증명 덤프·보호 해제 없이 기존 접근과 무해한 통신을 관찰했다.
- 7장은 실습 38·49의 로그 삭제·Defender 분석이다. 삭제·보호 해제·새 EICAR 생성 없이 기존 기록·상태·Wazuh 검색과 EVTX 보존을 확인했다.

- 9장은 실습 54~56의 Rootcheck·VirusTotal·ClamAV 분석이다. 현재 상태·규칙·수집 코드와 DQL을 확인했다. EICAR 생성·검사·삭제와 VirusTotal 활성화·외부 조회는 실행하지 않고 원전 결과와 독자 선택 절차를 구분했다.
- 10~13장과 부록을 작성했다. 각각 19·18·25·21·17쪽, 합계 100쪽이다. 현재 13장+부록의 초안을 갖추었다. 10·11장은 실습 57~61, 12·13장과 부록은 같은 Module 01의 후반 분석·점검 자료다.
- 10~13장과 부록은 읽기 조회·원전 분석·가정값 계산을 구분했다. 새 공격·수집 중지·설정 변경·합성 자료 적재/삭제를 수행하지 않았다. 각 장의 상세 검증 범위는 chapter01~13-review.md, appendix-review.md와 remaining-review.md를 따른다.
