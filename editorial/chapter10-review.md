# 10장 집필·검토 기록

2026-11-03. 「수집 장애와 자동 대응」, 19쪽. 실습 57·58, Module 01 583~601쪽. 준비·현재 상태 조회·기존 사건 분석·Wazuh 검색·조사·원상복구 순서다. 공통 출처와 검증 한계는 [전체 기록](remaining-review.md)을 따른다.

## 해석 교정

- 규칙 503은 시작, 504는 연결 단절, 506은 정상 종료 관련 기록이다. 503 하나로 재시작을 단정하거나 504를 악의적 중지로 확정하지 않는다. 강제 종료·경로 장애에서는 종료 기록이 없을 수 있다.
- disconnect_time 60초와 alert_time 0의 의미를 구분하고 정확히 60초에 화면에 나타난다고 보장하지 않는다. fw와 bastion이 함께 단절되면 공유 경로부터 점검한다.
- 651·652는 active response 입력의 add·delete 분류다. 실제 방화벽 적용·경로·서비스 영향까지 입증하지 않는다. 원인 경보는 parameters.alert 안에 있고 srcip도 중첩 경로로 조회한다.
- location local은 원인 이벤트의 에이전트다. 관리자에만 차단한다고 쓰지 않는다. 설정 timeout 180초와 기존 add·delete 간격 약 181초를 구분한다. 현재 iptables 기본 ACCEPT는 과거 차단의 부재를 증명하지 않는다.
- 중첩 원인 ID `1793619097.12602015`에는 규칙 5763이 있으나 직접 조회 문서는 5760이다. 같은 시각의 실제 5763 문서는 `1793619097.12600800`이며 포트도 44292와 44300으로 다르다. Q10-05 ID 검색과 Q10-06 규칙·호스트·주소 검색을 병행하고 관계를 확정하지 않는다.

## 검증

명령 11개를 구문 검사했고 상태·설정·기존 기록·현재 규칙을 읽었다. DQL 6개 결과는 27·4·2·2·1·1건이다. 에이전트 중지·네트워크 차단·인증 공격·자동 대응 재발동은 수행하지 않았다. 180초 차단의 종단 재현·실제 접속 영향·해제 실패를 새로 검증한 것이 아니다.

현재 상태 UI 두 장과 슬라이드 589쪽의 기존 연결 단절 화면 한 장, 도식 두 장, 통신함 삽화 한 장을 배치했다. 최종 19쪽을 개별 검토했다. 복사용 파일은 [examples/chapter10](../examples/chapter10/README.md), 조판·입력 대조는 [chapter10-qa.json](chapter10-qa.json)에 있다.
