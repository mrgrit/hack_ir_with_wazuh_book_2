## 확인한 범위

기존 로그·설정·규칙·프로세스·에이전트 상태를 SSH로 읽었다. DQL 35개는 Wazuh Discover에서 Last 90 days로 직접 입력·검색하여 구문 오류가 없음을 확인했다. 각 검색식·시각·건수는 `remaining-query-ui.json`에 있다. 12·13장의 합성 문서는 현재 환경에 없어 0건이었다. 빈 결과를 원전의 양성 결과나 공격 경로 검증으로 바꾸지 않았다.

Dev Tools 본문과 같은 GET 요청을 인덱서 내부의 CA 검증 TLS 연결로 조회했다. 저자용 curl 래퍼는 기존 인증서 파일을 참조했으며 키 내용을 읽거나 저장하지 않았다. 독자용 Dev Tools 클릭·붙여넣기 전체를 재현한 검증은 아니다. 19개 셸 입력은 Bash 파서, C10-01은 PowerShell 파서로 확인했다. 대화형 less 키 입력·최초 SSH 신뢰 화면·컨테이너 전환은 독자 절차이며 저자용 읽기 래퍼의 실행과 구분한다.

합성 자료 생성·적재·삭제, 새 공격, 에이전트 중지, 방화벽·보호 설정 변경, 서비스 재시작은 수행하지 않았다. 독자 선택 생성 명령 C12-01~03의 파일 생성·해시 결과는 예상 확인 기준이다. 점수표와 시간 연습표는 명시적으로 만든 가정값이며 관측된 IP 점수나 운영 성능이 아니다. 끝의 읽기 확인에서 여섯 에이전트가 Active였다. 조회 과정의 접속·감사 기록은 삭제하지 않았다.

## 증거 파일과 수정 이력

`evidence/remaining/2026-11-03/`의 preflight는 환경, details는 규칙·고정 소스·기존 대응 기록·Suricata 모드, index-info는 버전 응답, cause-id는 원인 식별자 대조다. request-checks에는 최초 GET·현재 자료의 산술 확인·19개 구문 검사·마지막 에이전트 상태가 있다. **최종 D12-01은 fieldcaps-final-check, 최종 시간 집계는 hourly-final-checks를 우선한다.** 최초 입력과 최종 입력이 다른 기록을 혼동하지 않는다.

- `pgrep -a suricata`는 프로세스 이름 Suricata-Main과 맞지 않았다. 전체 명령줄의 시작을 찾는 `pgrep -a -f '^suricata '`로 고쳤다.
- ips 내부에는 iptables가 없었다. 연구용 조회 stderr를 보존했으며 iptables가 없다는 사실을 방화벽 부재로 해석하지 않았다. nft와 실행 옵션을 따로 읽었다.
- field_caps의 긴 URL을 줄이려던 JSON 본문 fields 배열은 현재 서버에서 400 오류였다. 최종 입력은 `GET wazuh-alerts-*/_field_caps?fields=*`로 바꾸어 성공 응답을 확인했다. 모든 필드 중 필요한 매핑을 찾도록 설명한다.
- moving_fn의 기본 gap 처리에서는 비어 있는 버킷에 risk_24h가 없었다. `gap_policy: insert_zeros`와 `shift: 1`을 적용한 최종 요청을 다시 확인했다. 빈 합성 범위 47버킷과 현재 자료 72버킷의 이동 합을 별도로 대조했다.
- 원전의 86601 가중치 출력 0.63은 제시된 산식·입력으로 계산하면 0.6355, 소수 둘째 자리 반올림 0.64다. 원전 수치와 재계산을 구분했다.
- 자동 대응의 중첩 원인 ID와 직접 조회된 규칙의 불일치는 미해결 조사 사항으로 남겼다. 확인하지 못한 원인을 만들어 설명하지 않았다.

인증을 담는 로컬 래퍼는 ignored build에 있다. 인용한 공개 소스 중 암호 기본값을 포함한 줄은 커밋 증거에서 가렸으며 원문 SHA256과 가림 위치를 기록했다. 경보의 “Failed password” 같은 사건 본문은 인증 비밀이 아니므로 보존했다.

## 그림과 조판

화면 12개 중 현재 UI와 원전의 출처·원본 해시·직사각형 자르기 영역은 `remaining-screenshot-provenance.json`에 있다. 실제 UI 값을 그리거나 덮어쓰지 않았다. 현재 빈 결과와 원전의 합성 결과를 캡션·본문에서 구분했다. source-ip 화면의 마지막 불완전한 행을 제거하고, MITRE·일일 검색 화면은 핵심 영역의 지면 폭을 조정했다.

인물 네 장 중 세 장은 사무실이다. 일일 기록을 쓰는 남성, 모니터와 자료를 비교하는 여성, 회의실 시간선을 검토하는 남성으로 작업·구도·소품을 달리했다. 10장은 수집 연결과 관련된 통신함 장면이다. 사용자가 지적한 11장 최초 그림의 몸통·다리 불일치를 수정한 생성본을 사용했다. 거절된 원본은 산출물에 넣지 않았다. 원본과 삽입 지면을 각각 열어 어깨·팔·손, 몸통·골반·허벅지·무릎·발, 의자 지지, 문서·모니터 방향과 투명 여백을 확인했다. 프롬프트와 선택 파일은 `remaining-illustrations.json`에 있다.

base DOCX를 열어 판형·여백·테마를 상속했다. 숨긴 Word COM으로 내부 PDF를 만들고 최종 100쪽 모두 개별 확인했다. 수정 뒤 동일한 페이지는 PNG 해시로 일치를 확인하고 변경된 페이지는 다시 열었다. 표·코드·캡션·전체 URL, 그림의 종횡비와 내장 해시를 대조했다. 검토 기록은 장별 `*-qa.json`과 `remaining-delivery.json`을 따른다. 후속 사용자 교정은 각 DOCX를 대상으로 한다.
