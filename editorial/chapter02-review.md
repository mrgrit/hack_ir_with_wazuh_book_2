# 2장 출처와 검증 기록

2026-11-03. Module 01 실습 31~34, PPTX 순서 349~386을 책의 준비·입력·응답·원본 확인·Wazuh 검색·조사·원상복구로 재구성했다. 원전 URL과 기준 커밋은 본문 참고자료에 전체 주소로 인쇄했다.

## 실제 확인

- 환경: kt66 192.168.0.107, KT66-WIN-01, windows-user/005. 입력 위치는 내부 kt66-attacker이며 외부 공격자 VM과 구분한다.
- Hydra 9.2로 틀린 암호 2개, 없는 이름 3개, 틀린 암호 5개를 각각 한 차례 입력했다. 저자 실행에는 60초 timeout을 추가했으며 시간 제한 전에 종료했다. 본문은 동일한 후보·동시성·목적지를 한 명령씩 입력하는 절차다.
- 4625 기록 9976·9978은 SubStatus 0xc000006a, 10036·10038·10040은 0xc0000064였다. Status는 0xc000006d였다. LogonType 3과 원본 주소 10.20.30.202를 대조했다.
- 4740 기록 10103, Lockout True를 확인했다. 잠금 기간 경과 후 False가 됐다. Windows 메시지의 Caller Computer Name attacker가 XML TargetDomainName 및 Wazuh targetDomainName에 대응함을 확인했다. Subject는 시스템 문맥이며 공격자 이름이 아니다.
- FreeRDP 2.6.1에 /cert:tofu, 25초 timeout을 사용했다. 4624 기록 10207, 유형 10, victim, 주소 10.20.30.202, TargetLogonId 0x1ca2207을 확인했다. 기존 콘솔 세션으로 인해 LOGON_MSG_BUMP_OPTIONS가 표시됐으며 원격 바탕 화면 작업을 수행했다고 주장하지 않는다.
- Discover에서 Q02-01~07을 실제 실행했다. Last 24 hours 범위 결과는 순서대로 7·7·3·1·0·1·10건이었다. UI 갱신 전의 오래된 결과 수를 제외하고 해당 이벤트 행이 표시된 후 다시 확인했다. 기록은 evidence/chapter02/2026-11-03/dql-ui.json이다.
- 실제 화면 6개를 CUA 브라우저 스크린샷으로 저장했다. 기록 9978·10040·10103·10207의 필드를 원본 XML과 대조했다. 5개 화면은 잘린 마지막 행과 기록 번호가 모두 보이도록 다시 촬영했다. UI를 생성하거나 합성하지 않았다.

## 원전에서 수정한 해석

- 관리자·Guest 이름을 미존재 계정으로 가정하지 않고 사전 조회에서 없는 이름 세 개를 사용했다.
- 4740은 로컬 계정에서도 발생한다. Enabled와 Lockout을 구분했다.
- Status와 SubStatus를 함께 검색한다. 0xc0000234가 없더라도 4740과 현재 잠금 상태로 잠금을 확인할 수 있다.
- 루프백 제외 조건은 공인 외부 주소 조건이 아니다. 원본 주소와 에이전트 주소를 구분했다.
- 성공 로그온은 원격 데스크톱에서 후속 명령을 실행했다는 증거와 다르다. 실패 뒤 성공도 암호를 알아낸 동일 공격자의 행동으로 단정하지 않는다.
- 인증서 검증 무시 대신 TOFU의 첫 신뢰와 변경 감지 범위를 설명했다.

## 원상복구와 미실행 분기

cleanup.json에 세 목록 파일과 실습 디렉터리 제거, 이번 접속에서 처음 생성된 단일 대상 known_hosts2 제거, xfreerdp 종료를 기록했다. victim Enabled True·Lockout False, 기존 kt66student 콘솔 세션, Defender 두 보호 상태 True를 확인했다. 감사·잠금 정책을 바꾸지 않았으며 이벤트와 LastLogon은 관찰 이력으로 남겼다.

C02-19·25·26A의 기존 캐시 백업·복원 분기는 이 환경에 사전 캐시가 없어 실행하지 않았다. C02-23 로그오프도 남은 victim 세션이 없어 실행하지 않았다. C02-25A의 신규 캐시 제거 분기는 실행했다. 명령을 모든 환경에서 일괄 실행 검증한 것으로 표시하지 않는다.
