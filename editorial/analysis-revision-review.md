# 2권 Wazuh 분석 전수 점검·보강 — 2026-11-04

## 요청과 판단

사용자는 6장에 Wazuh 분석이 적은 이유를 확인한 뒤, 보강하고 다른 장도 전체 점검하여 다시 작성하도록 요청했다. 대상은 2권 1~13장과 부록의 별도 DOCX 14개다. 기존 실습 설명을 폐기하는 대신, 검색 이후 원본 연결·결과 해석·대응 판단·종결 근거가 부족한 부분을 각 장의 실제 사례로 보강했다. 같은 일반 점검표를 모든 장에 반복 삽입하지 않았다.

6장에는 이미 Sysmon 10·3·22의 수집·필드 해석이 있었다. 그러나 원본과 경보의 직접 비교, 생성 명령에서 통신으로 이어지는 실제 검색, DNS 응답 뒤 연결 여부의 조회와 완성된 조사 결론이 부족했다. 따라서 전개상 Wazuh 분석을 생략하는 장이 아니라 **분석 절차의 보강이 필요한 장**으로 판단했다.

## 검증 범위

- 기존 실습망을 읽기 전용으로 조회했다. 새 공격·덤프·자격증명 추출·보호 해제·수집 중지·설정 변경·로그 삭제·합성 자료 적재를 수행하지 않았다. 본문의 이전 실습 관찰 결과는 해당 장의 기존 검토 기록을 따른다.
- 신규 DQL 22개를 Wazuh Discover에서 입력했다. Q06-10을 두 데이터 보기에서 실행하여 총 23개 검색/인덱스 조합을 확인했다. 구문 오류 없이 관찰한 건수와 0건 결과를 `evidence/analysis-revision/2026-11-04/dql-ui-results.json`에 보존했다. 0건은 대상·기간·보존 자료에 한정한다.
- 보충 GET 요청 두 개는 실제 인덱서의 `_search`에서 실행했다. UI에 입력한 DQL과 인덱서 GET 실행을 구분한다. 입력 JSON과 응답을 `aggregation-responses.json`에 보존했다. 이 두 GET을 Dev Tools UI에서 직접 실행했다고 주장하지 않는다.
- 기존 로그의 원문·필드를 조회하여 `evidence.json`, `followup.json`에 필요한 필드만 남겼다. 전체 명령줄·full_log에는 실습 인증 정보가 있을 수 있어 공개 증거에서 제외했다. 조회 시각과 이벤트 원본 시각을 따로 보존했다.
- 읽기 조회를 위한 저자용 SSH·컨테이너 호출은 독자 절차의 대체물이 아니다. 독자 본문은 기존 브라우저·대화형 컨테이너·한 블록씩 입력하는 절차를 유지했다.
- 오프라인 wazuh-logtest에 기존 JSON 원문 3개를 넣은 별도 점검은 일반 JSON 디코딩 단계까지만 관찰했다. 운영 EventChannel 수집 경로와 같다는 근거가 없어 특정 규칙 제외 원인의 증명으로 사용하지 않았다.
- 조회 당시 logall_json=yes, log_alert_level=3이었다. 같은 Sysmon 원본 여섯 건은 archives 6건, alerts 0건이다. 생성 경보 92057·파일 생성 경보 92213을 통신 이벤트의 탐지로 바꾸어 해석하지 않았다. 경보 제외의 상세 규칙·저장 이력은 추가 조사 항목으로 남겼다.
- 12장의 실제 IP는 69건, 레벨 5 이상 47건, 최대 레벨 10, 규칙 15종, 수집 에이전트 3개, 관찰 날짜 2일이다. 에이전트 수를 공격 대상 시스템 수로 치환하지 않았다. 동일 호스트 5760 세 건의 중앙 시각 차이는 22.020초·24.024초다.
- 13장의 선택 IP·시간 구간은 49건이다. 레벨 5×32건, 8×2건, 10×3건, 3×12건이며 레벨 5 이상 제곱 합은 1228이다. 첫 성공은 반복 실패 경보보다 앞선다. 과거 4주 자료의 완전성이 없어 신규 IP 판정은 보류했다.
- 위 확인은 추가한 조회와 해석의 검증이다. 모든 장의 공격·실패·보완·원상복구 분기를 새로 실행 검증한 결과가 아니다. 현재 없는 합성 자료·원전 양성 파일 사례는 계속 원전 분석 또는 가정값 연습으로 구분한다.

## 산출물·조판·재생성

최종 장별 페이지 수는 31·40·42·38·38·46·37·36·41·20·21·28·23쪽과 부록 18쪽, 합계 459쪽이다. 6장은 38쪽에서 46쪽으로 늘었다. 이는 별도 DOCX의 본문 지면 합계이며 합본의 최종 출판 페이지 수가 아니다.

DOCX 14개를 Windows Word로 렌더했다. 전체 459쪽 중 이전 승인본과 본문 픽셀 해시가 같은 297쪽은 대응 페이지를 기록했고, 달라진 162쪽은 개별 페이지 이미지로 직접 확인했다. 페이지 번호는 전체 페이지에서 별도 확인했다. 교정한 두 화면과 12장의 집계 설명으로 바뀐 지면도 다시 확인했다. 표·명령·검색식·캡션·화면·전체 참고 URL의 잘림과 겹침을 점검했다. 문서별 해시와 페이지별 확인 방식은 `analysis-revision-qa.json`에 있다.

본문 입력 333개는 JSON·복사용 파일·DOCX와 대조했다. 신규 DQL은 22개이고, 별도 보충 GET 완성 요청은 2개다. 템플릿 판형·여백, 그림 내장 해시, 참고 URL 전체, 인증 토큰 패턴을 점검했다. 보강 함수를 두 번 적용해도 내용이 중복되지 않는 것을 14개 원고에서 확인했다.
