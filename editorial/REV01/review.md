# 2권 REV01 교정 기록

## 범위와 편집 기준

사용자가 제공한 명저·문체·구성·편집 검토 의견을 바탕으로 2권 1~13장, 부록, 참고문헌을 순차 교정했다. 병렬 에이전트를 사용하지 않았다. 이번 요청이 2권 REV01의 신규 작성·GitHub 업로드를 명시했으므로 기존의 REV01 보존 지침과 구분한다. 1권, 기존 2권 초안, 강의 저장소는 수정하지 않았다. 작업 시작 시 이미 수정 중이던 삽화·초안·공용 조판기의 변경도 이번 커밋에 섞지 않는다.

출발점은 이 저장소의 `6b857666681ff642ef31d8dd08857fa23deef1e2`와 작업 시작 당시의 초안이다. 작업 시작 시점 초안 28개 파일의 SHA-256은 `source-baseline.json`에 있다. 삽화는 당시 최신 교정본을 별도 `assets/REV01`으로 고정했다. 다른 대화에서 확보한 1권의 편집 검토 기준과 이번 대화의 직접 지시를 적용했다. 조회되지 않은 과거 대화 전체를 읽었다고 간주하지 않는다.

책의 주장은 **경보를 침해 판정으로 옮기려면 원본·수집 범위·연결 근거·실제 결과를 확인해야 한다**는 것이다. 장마다 다른 실습을 한 공격자의 실제 캠페인으로 합치지 않았다. 대신 대상·시각·입력·원본·경보·판단·남은 확인·원상복구라는 조사 기록을 뒤 장으로 이어 간다.

## 적용한 변경

- 장 앞에 구체적 조사 장면, 학습목표 세 가지, 확인 전 예측 질문을 배치했다.
- 설명의 인과와 다음 조사 행동을 연결했다. 용어는 조사 대상과 함께 설명하고, 핵심 명령의 목적과 구문을 분리했다. 복잡한 옵션·기호·실행 위치·확인 결과는 유지했다.
- 실습·주의·현장 노트·보이지 않는 것 상자를 구분했다. 현장 노트는 일반적인 조사 판단이며 저자의 은행 경력이나 실제 사건 경험을 만들어 넣지 않았다.
- 정상 행위 반례와 수집 공백을 보강했다. 전반부는 기록 식별, 중반부는 연결 근거 선택, 후반부는 귀속·집계·종결 판단을 스스로 수행하게 했다.
- 장말을 핵심 정리 → 확인 문제 → 스스로 조사하기 → 다음 장 연결 → 주석이 있는 더 읽을거리로 맞췄다. 독립 과제 13개의 판단 근거와 확인 문제 해설은 부록에 모았다.
- 쪽 목록을 연속 절 구조로 바꾸고 반복 절 제목·강제 쪽 나눔을 줄였다. 머리글과 실제 제목 스타일을 사용한다. 별도 DOCX마다 쪽 번호는 1부터 시작한다.
- 전체 URL 97개는 별도 참고문헌 DOCX에 인쇄한다. 장말은 주석이 있는 자료 2~3개와 참고 번호로 연결한다. 긴 URL에 임의 하이픈을 넣거나 글자를 줄이지 않았다.
- 입력 333개와 그림 124개를 보존하고, 로컬 자료 읽기 입력 CA-01~CA-04를 추가했다. 입력 예제 총 337개와 색인 CSV를 함께 제공한다.
- 보존 증거에서 필드 발췌본을 만들고 출처·SHA-256·JSON 위치·전체 검색 건수·보존 문서 수를 기록했다.
- 출처 텍스트의 SHA-256은 Git과 동일한 LF 줄바꿈 기준으로 기록했다. 작업 당시 CRLF 파일의 해시도 `source-line-endings.json`에 별도로 남겼다. 발췌 데이터의 값은 바꾸지 않았다.
- ATT&CK v16.1의 21개 기법을 공식 STIX와 대조하고 관찰 범위·부족한 증거를 지도에 표시했다. 기법 이름과 실제 악성행위 검증을 구분한다.
- 각 장의 탐지 개선을 설계·필요 필드·정상 반례·검사 결과로 기록하는 양식을 부록에 넣었다. 원문이 없는 규칙을 임의로 배포하거나 적용 완료로 쓰지 않았다.

## 원전에서 그대로 옮기지 않은 해석

지정된 Module 01의 로컬 PPTX 사본은 726슬라이드다. 해시·절별 위치는 `source-trace.json`에 기록했다. 이 교정에서는 전체 텍스트 목차와 해당 실습의 개요·결과 해석·후반 분석 설명을 대조했다. 모든 슬라이드의 UI를 새로 촬영하거나 새 실습으로 검증하지 않았다.

- 4624 유형만 보고 IIS 접속이나 전송 구간 평문을 판정하지 않는다.
- Sysmon 10의 접근 권한과 UNKNOWN callTrace만으로 덤프·인젝션을 확정하지 않는다.
- Office 이름의 부모 프로세스, 일정한 통신 간격, 긴 DNS 이름은 추가 조사 기준이다. 실제 매크로·C2·터널링 결과와 구분한다.
- Defender 5001·감사 변경·sudo 직후 단절에 공격자 의도를 자동 부여하지 않는다.
- 취약점 검색 0건은 수집 범위·스캔 시각·패키지·영향 조건을 확인한 뒤 해석한다.
- 두 엔진의 동일 파일 탐지는 업로드 경로를 확정하는 증거가 아니다.
- 같은 IP·8시간 창·같은 계정만으로 다른 호스트의 행위를 자동 연결하지 않는다.
- HTTP 200·SSH 성공·sudo 사용과 악용 성공을 구분한다. 합성 자료의 정답 라벨은 관찰 필드와 별도다.

## 검증 결과

1. 정적 검사: DOCX 15개, 입력 337개, 그림 124개, 기존 입력·캡션 보존, 복사용 파일 일치, 입력 참조, 127mm 표 폭, B5 188×263mm, 내장 그림 SHA-256을 확인했다. `static-check.json`의 오류는 0개다.
2. `check_rev01.py --check-originals`로 기존 초안 28개 파일의 해시가 작업 시작 시점과 같음을 확인했다. 이 기준에는 작업 시작 전에 있던 미커밋 수정도 포함하므로 새로 내려받은 저장소의 일반 검사는 해당 옵션 없이 수행한다. 원전 발췌 레코드가 기록된 출처의 해당 JSON 위치와 동일하다.
3. Windows Word로 개별 DOCX를 임시 PDF로 렌더했다. 총 492쪽의 본문을 144dpi 원래 크기로 열어 확인했다. 3·8장 끝의 불필요한 한 줄, 코드 양쪽 정렬, 부록 답안 순서 등을 고친 뒤 해당 지면을 다시 확인했다. 전체 텍스트 판면 이탈은 0쪽이다.
4. 문서별 전체 페이지 표본에서 머리글·꼬리말·판면을 확인했다. 모든 492쪽의 쪽 번호 연속성·B5 크기·본문 존재를 검사했다. 입력 337개와 전체 URL 97개가 렌더에 남아 있다. Word의 줄 끝 하이픈을 PDFium이 U+FFFE로 읽는 경우는 별도 pypdf 추출과 대조했다. `text-check.json`의 오류는 0개다.
5. 인물 삽화 24개 원본을 각각 열어 팔·손 연결, 엄지 방향, 몸통·골반·다리, 의자·책상, 문서·화면 방향을 확인했다. 문서에 들어간 실제 지면도 전체 검토에 포함했다. 이번 교정에서 새 인물 이미지를 생성하지 않았다.
6. Windows PowerShell에서 CA-01~CA-04의 로컬 읽기를 실제 실행했다. 파일 해시와 Record 9115, 6장 6건·0건 및 기록 번호를 확인했다. 이 검사는 VM 실습 재현 검사가 아니다.

## 이번 교정으로 완료했다고 하지 않는 항목

- 신규 PC·학생 베타 테스트: 시행하지 않았다. 새 Windows·VMware 설치부터 재현되는지는 별도 사용자 테스트가 필요하다.
- 전체 SIEM 복원 스냅샷: 제공하지 않는다. 현재 배포물은 출처가 있는 저장 필드 발췌본이다. 원문·인덱스 매핑·환경 전체를 복원할 수 없다.
- 90일 합성 데이터의 동일 결과 재현: 원자료가 없으며 새 생성·적재를 하지 않았다. 원전 값·보존 실습 조회·가정값 연습을 구분했다.
- 장마다 새 규칙 적용 후 공격 재실행: 수행하지 않았다. 필요한 필드와 정상 반례를 이용한 설계 과제를 제공하며 실제 적용·성공 검증으로 표현하지 않는다.
- 새로운 공격·VM 변경·UI 촬영: 수행하지 않았다. 보존 기록의 해석과 정적 문서 교정 범위다.

## 편집 원본과 재생성

`manuscript/REV01/*.json`이 편집 원본이다. DOCX는 검토·주석용 산출물이며 직접 고친 문장을 JSON에도 반영해야 재생성 시 유지된다. `tools/build_rev01.py`는 고정한 `rev01_components.py`, `tools/assets/bookk-B5.docx`, `assets/REV01`을 사용한다. 원고는 장별로 유지한다. 합본·배포 PDF는 만들지 않는다.

`prepare_rev01.py`, `polish_rev01.py`, `add_rev01_maps.py`, `package_rev01_examples.py`, `rev01_editorial_plan.py`와 `rev01_changes.json`은 최초 이관·교정 과정의 기록이다. 최종 JSON에 후속 수동 교정이 들어 있으므로 이를 재실행하여 최종 원고를 덮어쓰지 않는다. 일반 재생성에는 `build_rev01.py`만 사용한다.
